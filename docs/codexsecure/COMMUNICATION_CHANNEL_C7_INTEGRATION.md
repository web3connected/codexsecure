Through the gateway, `/secure/api/v1/status` and `/secure/api/v1/policy/zones` return 200, as do `/time/…/current-tiu` and `/hash/health`, all with the application key.

- **Expected change:** setting `SERVICE_API_KEY` activates the legacy `ServiceKeyMiddleware` on `/api/v1/zones`, `/zones/:code` and `/zones/detect`.
- **No live consumers were found.** Neither the Go nor the gateway logs had any `/zones` request. Laravel and the CodexWeb3 services do not call these routes. The only references are the CodexSecure TypeScript and Python SDKs, which already send `X-Service-Key` and now need the key configured.
- Through the gateway's generic proxy, which forwards no service key, `/secure/api/v1/zones` changed from 500 to 401. It was not working before.
- **Pre-existing and not caused by C7:** the legacy zone routes fail because `security_zones` does not exist in `codex_zones`. Go also warns `request_logs does not exist` at startup and on endpoint hits. The zone functionality in use, policy and alignment, is unaffected.

## 6. Remaining integration issues

None block C7. The items below are for the owners named.

1. **CodexTime TIU cache: not reproduced.** The running `codextime-api` returns `cached:false` even for reads 10 ms apart, and activation succeeded under concurrent polling of the public TIU route. The C4/C6 finding (a 1 s cache causing `503 CODEXTIME_UNAVAILABLE`) does not affect this CodexTime build. It would return if a caching CodexTime build were deployed, for example during the CodexTime restoration. That decision belongs to the CodexTime owner, and nothing was changed.
2. **Legacy zone tables (Web3Codex DB owner).** `security_zones` and `request_logs` are missing from `codex_zones` (pre-existing, §5).
3. **`.dockerignore` for `codexsecure_api`.** The `.env` file is in the Go builder-stage cache (§1). This is harmless locally but should be fixed before any shared or production build. It is outside C7's scope.
4. **The replay cache is per process.** That is correct for the single development container (C6 §2).
5. **The `other-site` grant case returns `CHANNEL_NOT_FOUND` rather than `SITE_NOT_FOUND`** for an unregistered site. That is the existing database function behaviour, and it does not reveal whether a site exists. Noted only.
